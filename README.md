# Teeth Manager

Додаток на React Native (Expo) для ведення статусу зубів та історії змін за нотаціями FDI.

## Що реалізовано

- **Головний екран** — схема зубів за FDI (верхня/нижня щелепа, права/ліва сторона, середня лінія). Зуби з історією підсвічені.
- **Клік по зубу** — перехід до екрану зуба з історією змін, можливість додавати, редагувати та видаляти записи (назва, нотатки, статус: здоровий, пломба, карієс тощо).
- **Глобальні процедури** — окремий екран для процедур на всю порожнину рота: чистка, відбілювання, фторування, огляд тощо.
- **Збереження** — дані зберігаються локально (AsyncStorage).

## Запуск

```bash
npm install
npm start
```

Далі відкрити в Expo Go на телефоні або емуляторі (iOS/Android), або `npm run web` для веб-версії.

## Структура проєкту

- `src/types.ts` — типи (ToothId, ToothChange, GlobalProcedure тощо), константи FDI.
- `src/store/teethStore.ts` — робота з даними (завантаження/збереження, додавання/редагування записів).
- `src/components/DentalChart.tsx` — схема зубів з кнопками по кожному зубу.
- `src/components/ToothButton.tsx` — одна клікована «зуб».
- `src/screens/ChartScreen.tsx` — головний екран зі схемою та переходом до глобальних процедур.
- `src/screens/ToothDetailScreen.tsx` — історія змін одного зуба, модалка додавання/редагування.
- `src/screens/GlobalProceduresScreen.tsx` — список глобальних процедур та додавання нових.

## Ідеї для розширення функціоналу

1. **Поверхні зуба** — для кожного запису вказувати поверхні (мезіальна, дистальна, буквальна, лінгвальна, оклюзійна) для детальнішого обліку пломб/карієсу.
2. **Типи лікувань** — окремі типи подій: пломба, видалення, коронка, кореневе канал, імплант тощо, з можливими датами наступного огляду.
3. **Нагадування** — push-сповіщення про запланований візит, повторну чистку або контрольний огляд конкретного зуба.
4. **Фото** — прив’язка фото до зуба або до візиту (до/після лікування).
5. **Кілька профілів** — перемикач пацієнтів (наприклад, для родини) з окремим набором даних для кожного.
6. **Експорт/резервна копія** — вигрузка історії в JSON або PDF для збереження або передачі лікарю.
7. **Статистика/аналітика** — які зуби найчастіше лікували, кількість процедур за період, напоминание про зуби без огляду давно.
8. **Тема інтерфейсу** — світла/темна тема.
9. **Синхронізація** — опційна хмара (наприклад, власний бекенд або Firebase) для резерву та доступу з кількох пристроїв.

Можна поступово додавати ці пункти в залежності від пріоритетів.
